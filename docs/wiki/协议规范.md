# 协议规范

版本 1。定义在 `app/src/main/kotlin/host/msknet/sunsetripple/protocol/` 与 `transport/`、`session/` 中的若干编解码对象。

## 帧格式

所有链路共用同一种帧结构，多字节整数一律**大端**（BE）。

```
 0        1        2        3        4        5        6
 +--------+--------+--------+--------+--------+--------+-------------//
 |  type  |senderId|      seq        |   payloadLen    |   payload
 +--------+--------+--------+--------+--------+--------+-------------//
   1 字节   1 字节       2 字节 BE          2 字节 BE       0..512 字节
```

| 字段 | 宽度 | 取值 | 说明 |
| --- | --- | --- | --- |
| `type` | 1 B | 1..8 | 帧类型，见下表 |
| `senderId` | 1 B | 0..255 | 发送者成员 ID，房主固定为 `0` |
| `seq` | 2 B BE | 0..65535 | 序号，溢出回绕（`and 0xFFFF`） |
| `payloadLen` | 2 B BE | 0..512 | 负载长度 |
| `payload` | 变长 | —— | 见各类型编码 |

常量：`HEADER_SIZE = 6`，`MAX_PAYLOAD = 512`。

构造超过 512 字节负载的帧会直接抛异常；`FrameType.from(id)` 遇到未知类型抛 `IllegalArgumentException("未知帧类型 $id")`。

## 帧类型

```kotlin
enum class FrameType(val id: Int) {
    AUDIO(1), JOIN(2), ROSTER(3), PTT_STATE(4),
    PING(5), LEAVE(6), HOST_TRANSFER(7), HOST_SNAPSHOT(8)
}
```

| ID | 类型 | 方向 | 负载 |
| --- | --- | --- | --- |
| 1 | `AUDIO` | 双向 | Opus 编码帧 |
| 2 | `JOIN` | 客户端 → 房主 | 令牌 + 端点 + 昵称 |
| 3 | `ROSTER` | 房主 → 单个客户端 | 个性化花名册 |
| 4 | `PTT_STATE` | 双向（仅蓝牙） | 1 字节布尔 |
| 5 | `PING` | 客户端 → 房主 | 空 |
| 6 | `LEAVE` | 双向 | 空 |
| 7 | `HOST_TRANSFER` | 房主 → 各成员 | 转移计划 |
| 8 | `HOST_SNAPSHOT` | 房主 → 各成员 | 同上结构，作为容灾快照 |

## 分帧

TCP 与 RFCOMM 是字节流，需要 `FrameStreamReader` 按长度前缀切分。它是阻塞式的，遇到 EOF 或 `payloadLen > MAX_PAYLOAD` 返回 `null`。调用方一般用 `readFrameSafely()` 包一层，把协议错误转成 `null`，语义为「丢弃这个对端，不影响房间其他人」。

UDP（WiFi 音频）与 Nearby BYTES 负载是天然定界的，一个数据报 / 一个负载恰好一帧。Nearby 侧还额外校验 `bytes.size == HEADER_SIZE + payloadSize`，不等则断开该端点。

## 各类型负载编码

### JOIN

入房与**重连恢复身份**共用这一帧，有两个版本。

**v1：**
```
[0x01][token 16B][nickname UTF-8...]
```

**v2：**
```
[0x02][token 16B][endpointLen 1B][endpoint ASCII][nickname UTF-8...]
```

- `token`——16 字节 `SecureRandom` 值，房主以小写十六进制为键保存。**重连时凭同一令牌恢复原成员 ID 与入房顺序**；令牌不符则无法占用保留位。
- `endpoint`——稳定的重连/接管标识。WiFi 房为 P2P 设备地址（过滤掉 `02:00:00:00:00:00` 这个匿名占位值），蓝牙房由服务端从 `connection.remoteAddress` 推导，因此 `BluetoothClientTransport` 发送 v1 即可。
- `nickname`——UTF-8，按与花名册一致的规则截断。

解码会拒绝：版本号错误、令牌不足 16 字节、负载超限、UTF-8 非法。令牌在解码时做防御性拷贝。

### ROSTER

```
[yourId 1B][memberCount 1B]
  重复 memberCount 次:
    [id 1B][nickLen 1B][nick UTF-8][ipLen 1B][ip ASCII]
```

- 昵称按 UTF-8 **字符边界**截断到 `MAX_NICK_BYTES = 60`，不会切出半个汉字。
- 花名册是**个性化的**——每个接收者的 `yourId` 不同，因此必须单播，不能广播。
- 由 `RosterFrames.encode(hostId, yourId, members)` 生成；负载超限时返回 `null` 并记日志，而不是抛异常。
- `ip` 字段按房型有不同含义：WiFi 房是 IP 地址；蓝牙房中房主自己填字面量 `"host"`，客户端填蓝牙 MAC；Nearby 房中房主自己填 `"host"`。

### PTT_STATE

恰好 1 字节：`0` = 松开，`1` = 按下。其他值抛异常。仅蓝牙房使用。

### PING

空负载。仅客户端发送，间隔 3 秒（`PING_INTERVAL_MS = 3_000L`），用于让房主的读超时保持活跃。

### LEAVE

空负载。主动离房时发送，房主收到后立即释放该成员位置。

### HOST_TRANSFER / HOST_SNAPSHOT

两者结构完全相同，区别在语义：`HOST_TRANSFER` 是「现在就执行转移」，`HOST_SNAPSHOT` 是「存着，万一我挂了就按这个来」。

```
[version=1 1B][successorId 1B][memberCount 1B]
  重复 memberCount 次:
    [memberId 1B][joinOrder 8B][nickLen 1B][nick UTF-8][endpointLen 1B][endpoint ASCII]
```

解码会拒绝：版本号非 1、成员数不在 `1..6`、端点含非 ASCII 字符、UTF-8 非法、存在多余尾字节。计划校验还要求成员 ID / 端点 / 入房顺序三者各自唯一，继任者必须在成员列表内，且 `successorId in 1..255`。

详见 [房主转移机制](房主转移机制.md)。

## 传输层差异

### WiFi Direct

| 项 | 值 |
| --- | --- |
| 信令端口 | TCP `8988` |
| 音频端口 | UDP `8989` |
| 房主 IP | `192.168.49.1`（Android WiFi Direct 组主固定地址） |
| 房主成员 ID | `0` |
| 最大成员 | 6 |
| UDP 缓冲 | 2048 B |
| 握手超时 | 5000 ms（首帧必须是 JOIN） |
| 读超时 | 10000 ms |
| 客户端连接超时 | 5000 ms |
| 重连宽限 | 7000 ms |

信令（JOIN / ROSTER / PING / LEAVE / HOST_TRANSFER / HOST_SNAPSHOT）走 TCP，音频走 UDP。

**音频是网状直发，不经房主转发**——客户端把 AUDIO 数据报发给花名册中除自己外的每个成员 IP，组主只是普通参与者。

`broadcast()` 在两侧都用 `require` 拒绝 HOST_TRANSFER 与 HOST_SNAPSHOT，因为这两种帧必须定向单播。

### 蓝牙 RFCOMM

| 项 | 值 |
| --- | --- |
| 服务 UUID | `7f75d4e0-7a46-4d74-9f8d-1e4bc5e4b003` |
| 服务名 | `SunsetRipple Bluetooth Room` |
| 安全模式 | 默认安全；房主转移后重建时使用非安全模式 |
| 可被发现时长 | 300 秒 |

只有一条可靠流，信令与音频复用。星型拓扑下：`sendTo(memberId, frame)` 用于定向发送 AUDIO，`broadcastSignal(frame)` 用于其余帧（并用 `require` 拒绝 AUDIO / HOST_TRANSFER / HOST_SNAPSHOT）。

**房主重写发送者身份**：收到的帧被重新封装为 `Frame(frame.type, client.id, frame.seq, frame.payload)`，客户端自报的 `senderId` 不被信任。

### Nearby Connections

`Strategy.P2P_CLUSTER`，`SERVICE_ID = "host.msknet.sunsetripple"`，一帧一个 `Payload.Type.BYTES`。客户端只向 `member.id > selfId` 的对端发起连接，避免双向重复建链。

## 重连

`ReconnectPolicy` 的退避序列为 `[1000, 2000, 4000]` 毫秒，三次之后 `nextDelayMs()` 返回 `null` 表示放弃。收到花名册或链路恢复时 `reset()`。

房主侧为断线成员保留位置 7 秒（`RECONNECT_GRACE_MS`）；房主转移后继任者对未重连成员的保留同样是 7 秒（`TRANSFER_RESERVATION_GRACE_MS`），到期释放以免永久占用房间容量。
