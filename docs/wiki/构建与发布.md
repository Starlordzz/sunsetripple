## 常用命令

```powershell
# 1. 获取依赖包
flutter pub get

# 2. 运行自动化单元测试 (58 个用例)
flutter test

# 3. 运行代码静态分析
flutter analyze

# 4. 在真机上调试运行
flutter run

# 5. 打包 Release 发布版 APK
flutter build apk --release
```

## 发布签名

### 密钥与配置

签名配置和密钥**只存在于本地**，不进入版本库。`.gitignore` 已排除 `keystore.properties`、`*.jks`、`*.keystore`、`*.p12`。

`keystore.properties` 格式见 `keystore.properties.example`：

```properties
storeFile=C:/Users/<用户名>/.android/sunset-ripple-release.p12
storePassword=<强密码>
keyAlias=sunset-ripple
keyPassword=<强密码>
```

> **同一密钥必须长期沿用。** Android 以签名证书标识应用来源，换密钥后已安装的用户无法覆盖升级，只能卸载重装。请离线备份 `.p12` 与密码。

### 签名守卫

`app/build.gradle.kts` 注册了 `verifyReleaseSigning` 任务，并挂在 `packageRelease` / `bundleRelease` 之前。缺少配置文件、缺字段或密钥文件不存在时，构建会**提前失败**并给出中文原因，避免产出未签名或错签的包。

### 打包

```powershell
$env:JAVA_HOME='C:\Path\To\jdk-17' # 替换为本机 JDK 17 安装目录
.\gradlew.bat :app:testDebugUnitTest :app:lintRelease :app:assembleRelease :app:bundleRelease
```

产物：

- 可侧载 APK：`app/build/outputs/apk/release/app-release.apk`
- 应用商店 AAB：`app/build/outputs/bundle/release/app-release.aab`

CI 或临时签名配置可用 Gradle 属性指向别处（接受绝对路径）：

```bash
./gradlew :app:assembleRelease -PsunsetRipple.signingProperties=/secure/path/keystore.properties
```

### 发布到 GitHub Release

已发布版本见 [Releases](https://github.com/Starlordzz/sunsetripple/releases)。`.github/workflows/release.yml` 会在推送 `v*` Tag 后自动完成测试、Release lint、签名 APK/AAB、`update.json` 清单签名和 GitHub Release 上传。

首次启用前，在 GitHub Actions Secrets 配置 `ANDROID_KEYSTORE_BASE64`、`ANDROID_KEYSTORE_PASSWORD`、`ANDROID_KEY_ALIAS`、`ANDROID_KEY_PASSWORD`、`UPDATE_PRIVATE_KEY_PKCS8_BASE64`，并配置非敏感变量 `UPDATE_PUBLIC_KEY_BASE64`。更新私钥与 Android keystore 必须离线备份。

发布步骤：

1. 更新 `versionCode` / `versionName` 与 `CHANGELOG.md`。
2. 提交变更并创建同名 Tag，例如 `v0.1.0-alpha.6`。
3. 推送 Tag：`git push origin v0.1.0-alpha.6`。
4. Actions 自动创建版本 Release，并更新 `updates-prerelease` 或 `updates-stable` 滚动清单。

alpha / beta Tag 自动标记为 prerelease；手动运行 workflow 时，输入的 Tag 必须已存在且与 `versionName` 完全一致。

## 发布构建说明

当前发布构建为 `0.1.0-alpha.6`。更新协议会验证清单签名、APK SHA-256、包名和 Android 签名证书后，再交给系统安装确认。语音链路不依赖互联网，只有用户手动检查更新时才会访问 GitHub。
