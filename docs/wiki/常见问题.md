# 常见问题

## 使用相关

**要联网吗？要注册账号吗？**

都不要。没有服务器、没有账号、没有云端，语音只在建立了直连的设备之间传输。应用申请了 `INTERNET` 权限，但那是 socket 通信的系统要求，不用于访问互联网。只有在用户主动检查更新时才会连接 GitHub Releases。

**最多几个人？**

6 台设备，含房主。房主占成员号 1，另接 5 台；超出的加入请求会被拒绝，且不影响已在房内的成员。这个上限在会话层与传输层各自校验（没有单独的 `MAX_MEMBERS` 常量）。

**语音是怎么走的？**

星型拓扑：所有人只跟房主建立链路，语音帧由房主转发给其他成员，并不是设备之间两两直发。WiFi 房控制帧走 TCP 8988、语音走 UDP 8989，房主用 UDP 8990 广播房间信息；蓝牙房走 BLE L2CAP CoC，转发在原生侧完成。

**能传多远？**

WiFi 房（局域网 / 热点 / Wi-Fi Direct 直连）空旷环境约数十米，蓝牙房约 10 米。隔墙、身体遮挡都会明显缩短距离。

**耗电吗？**

WiFi 房更耗电——持续的 TCP/UDP 链路加上组播锁（MulticastLock）与前台服务。蓝牙房功耗低得多。长时间使用建议用蓝牙房。

**为什么蓝牙房不能同时说话？**

BLE L2CAP 的带宽撑不起多路全双工混音。与其做成断续、忽高忽低的全双工，不如做成可靠的按住说话。详见 [房间模式对比](房间模式对比.md)。

**为什么按住说话时听不见别人？**

有意为之——按住 PTT 期间本机播放静音，避免自己的声音经链路绕回来形成回声。松手即可听到。

**为什么点击创建房间后，房间会从按钮位置直接展开？**

展开区域绘制的就是实际房间界面，不是播放完再消失的过场遮罩。首页与房间共享同一套落日页头运动和配色，因此动画结束时不需要再切页，也不会出现黑帧或房间页面二次弹出。

**房主退出后房间就没了吗？**

WiFi 房不会：房间会依据房主周期性广播的交接快照，自动选出**仍在线的、最早入房的成员**接任并重建。房主主动离开或失联都能触发。**蓝牙房不支持房主转移**，房主退出即散会。详见 [房主转移机制](房主转移机制.md)。

**支持深色模式吗？多语言呢？**

都支持。配色分跟随系统 / 始终浅色 / 始终深色三档，入口在首页页头右上角，点击循环，选择会记住。浅色是落日暖色，深色是月与海面——两套配色共用同一份绘制代码。界面文案有简体中文与英文两套，跟随系统语言切换；字符串定义在 `lib/l10n/app_strings.dart`，这是 Flutter 项目，没有 `strings.xml`。

**能录音吗？能发文字吗？**

能发文字：房内可打开消息面板收发文本（协议帧 `FrameType.chat` / `chatSync` / `chatDelete`），纯内存存储、退房即毁，支持长按撤回。单条文本上限 368 字节 UTF-8；协议帧载荷上限是 512 字节。不支持录音和文件传输。

## 隐私相关

**语音会被上传吗？**

不会。没有服务器可上传。音频只经房主在已建立直连的设备之间转发。

**通话有加密吗？**

**默认明文传输。** 代码里有基于 AES-256-GCM 的应用层安全信封（`SecureFrameCodec`），但只有在给会话注入了 `secureCodec`（Dart 对象）时才会启用；未配置时安全性依赖底层链路。

如果你的使用场景对保密性有要求，请自行评估——这个项目的设计目标是「不联网也能说话」，不是「防窃听」。

**房间会留下什么记录吗？**

不会。没有数据库，没有日志持久化。聊天记录只在内存里，离开房间后本机清空。

## 构建相关

**需要什么工具链？**

Flutter SDK（版本范围见 `pubspec.yaml` 的 `environment`），Android 发布包另需 JDK 17 与 Android SDK。依赖由 `flutter pub get` 拉取。常用命令：`flutter pub get` / `flutter test` / `flutter analyze` / `flutter run` / `flutter build apk --release`。完整清单见 [构建与发布](构建与发布.md)。

**依赖下载失败怎么办？**

先重跑 `flutter pub get`；网络受限时为 pub / Git 配置镜像或代理。若是 Android 侧 Gradle 依赖下载失败，再单独处理 Gradle 的代理或镜像设置。

**为什么不用 NDK 编译原生 libopus？**

Android 用的是 Concentus 1.0.2——纯 JVM 的 Opus 实现，声明在 `android/app/build.gradle.kts`。代价是编解码走 JVM、CPU 开销略高；收益是构建不依赖 NDK、产物不含 `.so`。对 16 kHz 单声道 20 ms 帧这个量级，CPU 开销完全可以接受。

**iOS 上有 Opus 吗？**

目前没有。iOS 音频通道收发的是原始 PCM，尚未接入 Opus 编解码器，这是当前已知的跨平台差距。Android 侧已完整使用 Opus。

**为什么改了 `versionCode` 还是装不上？**

大概率是签名不同。Android 以签名证书标识应用来源，用不同密钥签的包无法覆盖安装。开发时装的 debug 包和 release 包也是两套签名，需要先卸载。

**Release 包怎么签名？**

发布签名从 `android/key.properties` 读取（该文件不入库）。文件不存在或字段不全时，`flutter build apk --release` 会退回使用 debug 签名，只能自测、不能发布。字段格式见 `android/app/build.gradle.kts` 中的注释。

**测试要模拟器吗？**

不要。测试全部是纯 Dart 单元与组件测试，可用 `flutter test` 直接运行，当前 144/144 通过，不需要模拟器。

## 项目相关

**能用在生产环境吗？**

当前处于 `0.1.0-alpha.13` 测试阶段，核心链路（WiFi 局域网/热点/直连全双工、蓝牙 PTT、房内文字消息、断线重连、WiFi 房主交接）均已跑通并覆盖自动化测试。注意 iOS 尚未接入 Opus，蓝牙房不支持房主转移与自动重连。建议作为近场应急对讲与学习参考使用。
