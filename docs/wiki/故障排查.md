# 故障排查

按症状分类。每条都先给最可能的原因，再给验证方法。

## 建不了房 / 搜不到设备

### 权限没给全

这是最常见的原因。应用需要的权限随 Android 版本变化很大：

| Android 版本 | WiFi 房需要 | 蓝牙房需要 |
| --- | --- | --- |
| 8.0 – 11（API 26–30） | 麦克风 + 精确定位 | 麦克风 + 精确定位 |
| 12（API 31–32） | 麦克风 + 精确定位 | 麦克风 + `BLUETOOTH_SCAN`（加入）或 `BLUETOOTH_ADVERTISE`（创建） |
| 13+（API 33+） | 麦克风 + `NEARBY_WIFI_DEVICES` + 通知权限 | 麦克风 + 蓝牙权限 + 通知权限 |

要点：

- **精确定位不能只给「大致位置」**——只给粗略定位仍会被拦截。
- **Android 13+ 通知权限是硬性前提**——前台通话服务需要它，拒绝会直接阻止入房。
- **Android 9–12（API 28–32）还必须打开系统的「定位服务」开关**，光给权限不够。这是系统层面对 WiFi / 蓝牙扫描的限制，与本应用无关。

应用内的拒绝提示会指明缺哪一项，照着开即可。

### WiFi Direct 建组失败

- 确认设备支持 WiFi P2P（少数定制系统阉割了这个能力）。
- 关掉可能抢占 P2P 通道的功能：热点、投屏、WiFi 直连文件传输（如各家的「互传」）。
- 部分机型省电模式会限制 P2P，先关省电模式再试。
- 建组时系统可能弹连接确认对话框，**需要手动点确认**，超时未确认会失败。
- 若提示「组主地址未就绪」并在 10 秒后返回首页，通常是 P2P 通道被占或系统未及时下发地址——关掉 WiFi 再打开，重试一次。

### 蓝牙搜不到房主

- 房主需要处于**可被发现**状态，有效期 300 秒；超时后重新创建房间。
- 先在系统蓝牙设置里配对一次，通常更稳。
- 经典蓝牙的发现过程本身较慢，等待 10–20 秒是正常的。

## 连上了但没声音

### 第一步：跑回环自测

首页进入回环模式，它在**单台设备上**跑完整音频链路（麦克风 → 编码 → 抖动缓冲 → 解码 → 扬声器）。

- **回环有声** → 音频栈正常，问题在网络链路，往下看。
- **回环无声** → 问题在本机音频，检查麦克风权限、是否被其他应用占用、音量。

### 音频焦点被抢

来电、导航播报、其他媒体应用会抢占音频焦点。本应用的策略是**降级为只听而不掉线**——所以界面还显示在通话中，但你说的话不发出去。

挂断来电或关掉抢占的应用即可恢复。注意：**焦点恢复不会自动解除你手动设置的静音**，这是有意为之，检查一下静音按钮状态。

### 只听模式

确认没有误触只听模式。界面上的静音状态和通知栏的控制按钮是同一份状态。

### 蓝牙房：忘了按住说话

蓝牙房是**按住说话（PTT）**，不是全双工。按住中间圆盘才发送，松手即收听。

另外，按住 PTT 期间本机播放静音——听不到别人是**正常行为**，为的是避免回声。松手后即可听到。

## 频繁掉线

### 距离与遮挡

- WiFi Direct：空旷环境数十米，隔墙衰减明显。
- 蓝牙：约 10 米，且身体遮挡就会显著影响。

把设备从口袋里拿出来，避免用身体挡在两台设备之间。

### 重连行为是什么样的

断线后会按 **1 秒 → 2 秒 → 4 秒**重试三次。期间界面显示「重连中」，成员位置被保留 7 秒。

- **重连成功** → 凭令牌恢复原成员 ID 与入房顺序，无需重新加入。
- **三次耗尽** → 若本机缓存了房主快照，会自动触发房主接管流程而不是直接散会；否则退出房间。

### 系统杀后台

前台服务 + WakeLock + WifiLock 已经尽力保活，但国内厂商的系统各有各的激进策略。若通话经常被无故中断：

1. 在系统设置里给应用加**电池优化白名单** / 「允许后台运行」。
2. 关闭针对本应用的「自动管理」或「智能省电」。
3. 在最近任务列表里**锁定**本应用。

### 房主换人了

房主离开或崩溃时，房间会自动选出继任者并重建。这个过程中：

- **蓝牙房**：重建较快，语音短暂中断。
- **WiFi 房**：需要重建 WiFi Direct 组，语音中断时间更长，**系统可能再次弹出连接确认对话框**——需要手动确认，否则重连失败。

详见 [房主转移机制](房主转移机制.md)。

## 音质问题

### 声音断续 / 卡顿

抖动缓冲的策略是**宁可丢，不可等**：迟到的包直接丢弃，丢包位置交给 Opus PLC 补偿。所以链路质量差时表现为轻微的断续而不是延迟累积。

改善方法：缩短距离、减少遮挡、避开 2.4 GHz 拥挤环境（微波炉、大量 WiFi 设备）。

### 蓝牙房音质明显不如 WiFi 房

这是设计使然。蓝牙房码率 16 kbps，WiFi 房 24 kbps；且蓝牙房音频要经房主混音转发，多一次编解码。

### 有回声

- 确认设备支持并启用了硬件回声消除（应用会自动启用 `AcousticEchoCanceler`，但部分机型没有）。
- 降低外放音量，或改用耳机。
- 两台设备离得太近（一米内）时，外放会直接串到对方麦克风，这不是软件能解决的。

## 安装问题

### 提示「应用未安装」或「包冲突」

装过包名为 `com.wt.intercom` 的旧测试版时会这样。包名已改为 `host.msknet.sunsetripple`，**无法覆盖升级，必须先卸载旧版**。

### 系统拦截安装

来自未知来源的 APK 需要在系统设置里允许对应的安装来源（浏览器 / 文件管理器）。
